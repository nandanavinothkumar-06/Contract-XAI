# Evidence and Rationale Extraction

## 1. Purpose
This module provides an evidence/rationale extraction layer to identify the specific text spans supporting a Legal-BERT model prediction. The purpose is EXPLANATORY EVIDENCE for model transparency, not legal interpretation. 

**Disclaimer**: The extracted evidence is model-derived attribution and should not be interpreted as a legal conclusion or proof of correctness.

## 2. Evidence Terminology
- **MODEL PREDICTION**: The classification output from the model.
- **MODEL-DERIVED EVIDENCE**: Evidence spans generated by our gradient attribution implementation.
- **GROUND-TRUTH EVIDENCE**: Evidence spans supplied by a human-annotated dataset (e.g., ContractNLI).
- **RATIONALE / EVIDENCE SPAN**: The exact source text mapped to high-scoring tokens.
- **SOURCE TEXT**: The exact original string before tokenization.

## 3. Evidence Schema
The `EvidenceSpan` schema securely maps the `source_start` and `source_end` integer characters to guarantee the invariant:
`source_text[source_start:source_end] == evidence.text`

## 4. Alignment Process
`TokenAligner` uses Hugging Face's `return_offsets_mapping` to safely align FastTokenizer offsets back to source character indices. It accurately handles padding, special tokens, punctuation, and multi-word token fragments. If alignment fails, `alignment_status = "FAILED"` is thrown and no false spans are emitted.

## 5. Attribution Method
The implemented method is **Gradient $\times$ Input Attribution**, a standard PyTorch-compatible technique taking the dot product of the embedding vector and its calculated gradient relative to the target logit.
*Reference: Shrikumar et al. (2017), "Learning Important Features Through Propagating Activation Differences", ICML 2017.*

## 6. Multiclass Handling
Target attribution calculates gradients specifically from the pre-softmax logit corresponding to the *selected predicted class* (or explicitly supplied target index).

## 7. Multilabel Handling
For multilabel objectives (like LEDGAR), logits are passed through a sigmoid function thresholded at 0.5. The gradients are computed against the specific logit of the targeted label. The rest of the logit vector is safely ignored to prevent overlapping rationales.

## 8. Truncation
If sequences exceed `max_sequence_length` (e.g., 512), the token aligner flags `truncated = True`. Model attribution is only computed over visible tokens. Evidence outside this window is never fabricated.

## 9. Ground-Truth vs Model-Derived Evidence
The schema explicitly separates `is_ground_truth` and `is_model_derived`. This ensures annotations from datasets like ContractNLI (when authorized) are never destructively overwritten or mixed with model-generated rationales.

## 10. Limitations
- Gradient × Input is a gradient-based, first-order attribution method. It provides model-derived gradient attribution. It does not by itself establish causal necessity, counterfactual validity, or legal correctness.
- Long document context is restricted by the absolute transformer token limit. Sliding windows are deferred to later tasks.
