# Baseline Models

This document describes the traditional machine learning baselines established for the ContractRisk-XAI framework. These baselines serve as reproducible quantitative reference points against which future proposed architectures (like Legal-BERT) can be evaluated.

## Baseline Motivation
To ensure a robust, scientifically grounded foundation, we must first determine how standard algorithms perform on the verified datasets. Traditional models offer fast training times, transparency, and established patterns of success for many NLP tasks, establishing a solid performance floor.

## Model Choices
1. **TF-IDF + Logistic Regression**: A standard, interpretable linear baseline.
2. **TF-IDF + Linear SVM**: Often yields stronger text classification margins on high-dimensional sparse representations.
3. **One-Vs-Rest Variants**: Used for multi-label formulations (e.g. `TFIDF_OVR_LOGISTIC_REGRESSION`).

## Feature Representation
Text is represented using TF-IDF (Term Frequency-Inverse Document Frequency) using `scikit-learn`:
- **N-grams**: `(1, 2)` (unigrams and bigrams).
- **sublinear_tf**: `True` to apply logarithmic scaling to term frequencies.
- **min_df**: Defaults to 1.

## Splitting Strategy and Leakage Prevention
We implement a **group-aware deterministic split**. Contracts (grouped by `source_document_id` or `contract_id`) must not span across the train/validation/test sets to prevent document-level data leakage. If an official dataset split exists (e.g. LEDGAR test splits), it is strictly prioritized. `check_leakage()` enforces this separation and fails experiments upon violation.

## Hyperparameter Policy
- **No Test Set Tuning**: Hyperparameters are fixed before running against the test set, preventing information leakage.
- **Randomness**: Deterministic initialization using random seeds (default 42) ensures reproducibility.

## Metrics
- **Multiclass/Binary**: Accuracy, Macro/Weighted F1, Macro Precision, Macro Recall.
- **Multi-label**: Micro F1, Macro F1, Hamming Loss.
- Imbalanced tasks prioritize **Macro F1**.

## Unavailable Tasks
Datasets unresolved in TASK 003 (e.g., CLAUDETTE, Construction datasets) will cleanly return `NOT_RUN_DATA_UNAVAILABLE`. The pipeline enforces that no results are fabricated.

## Interpretation of Baseline Results

To maintain absolute scientific clarity, baseline numbers are strictly categorized into one of three domains. These domains must **never** be mixed.

### Project Experimental Results
Actual experiments run on legitimate verified datasets within the project repository using the `BaselineExperiment` architecture. These results are saved directly to `results/baselines/` and reflect the local performance of models generated by this codebase.

### Test Fixture Results
Small deterministic fixtures used only to test the implementation architecture itself. These metrics are mathematically valid only for the miniature synthetic datasets they run on, and are deliberately partitioned into `results/test_fixtures/` to prevent benchmark pollution.

### Published Literature Results
Results reported by original authors in published papers (e.g. LEDGAR paper, ContractNLI paper). These baseline benchmarks remain strictly within the `references/` subsystem and are not falsely re-cast as experimental outputs of the ContractRisk-XAI system.
